# RCA — the 2026-07-18 → 07-28 failure cluster

_Written 2026-07-28. Scope: why a 10-day CI outage, an 11-day production bug, and a
near-miss on the production database all happened in the same fortnight._

## 1. What failed

| # | Failure | Cost |
|---|---------|------|
| F1 | e2e suite red — app blank-paged on boot (`supabaseUrl is required`) | 10 days; `main` frozen, 4 PRs queued |
| F2 | `projects.status` CHECK rejected `Closed`/`Archived` | 11 days live in production |
| F3 | Migration ledger drift — 42 timestamp versions vs `0001`–`0046` | 16 days undetected; `db push` would have replayed 46 migrations on the live DB |
| F4 | `db push` failed twice — constraints already existed from `0008`/`0017` | 2 failed attempts |
| F5 | `changes.status` CHECK rejects `Withdrawn` | 11 days live; **found by the test built from this RCA** |
| F6 | Three incorrect diagnoses during the investigation itself | wasted cycles, nearly shipped a wrong fix |

**Evidence:** `main` CI shows `failure` at `d493d69` (07-18) with no successful run until
07-28. `enforce_admins: false`. No CI job references `test:postgres`, `SUPABASE`, or any
database credential — **nothing in CI touches the real schema.**

## 2. Five Whys

### F2 — "Closed"/"Archived" broken in production

1. Why did it fail? The DB CHECK did not permit those values.
2. Why not? Migration 0038 defined the set as `(Active, Inactive, Complete, On Hold)`.
3. Why that set? Its author derived the vocabulary from live *data values* plus assumption,
   never cross-checking the UI dropdown or the `ProjectStatus` TypeScript type.
4. Why did an unverified vocabulary ship? Nothing compares a DB constraint against the code
   that writes to it.
5. **Why is there no such check?** The only enforced functional suite runs against the
   in-memory adapter, which has no schema and no constraints. The suite that *could* catch
   it (`test:postgres`) is deliberately excluded from CI because credentials are not
   available to it.

### F1 — e2e red for 10 days

1. Why red? The app crashed on boot in memory mode.
2. Why? The composition root statically imports all 12 Postgres adapters regardless of
   `VITE_ADAPTER`, so an eager `createClient(undefined, …)` threw at import time.
3. Why did that ship? Nothing tested "a memory build boots with no Supabase env" — which is
   exactly the configuration CI runs.
4. Why was the red not investigated for 10 days? It presented as a **1h17m timeout with no
   error message**, indistinguishable from infrastructure flakiness. The response was a
   `chore: retrigger CI` commit.
5. **Why was it illegible?** The signal was 30 × 30s Playwright timeouts. The actual cause
   (`supabaseUrl is required`) existed only inside a downloadable trace artifact.

### F3 — migration ledger drift

1. Why was `db push` unsafe? Ledger and repo had zero overlapping version names.
2. Why two schemes? The 07-12 migration was applied by a path that auto-generated timestamp
   versions; the repo names files sequentially.
3. Why undetected for 16 days? Nothing compares repo migrations to the ledger.
4. Why did nobody run `migration list`? Migrations were reaching the DB by other means, so
   the CLI view was never consulted.
5. **Why out-of-band?** One Supabase project serves both dev and production. There is no
   rehearsal environment, so applying directly is the path of least resistance. (= issue #26,
   and the direct cause of incident P3-0.)

## 3. Root cause

Every failure has the same shape:

> **Two representations of one fact diverged, and nothing existed to detect the divergence.**

- UI dropdown ↔ DB CHECK (F2, F5)
- Repo migrations ↔ DB ledger (F3)
- Declared TS types ↔ actual DB values (`DistributionMethod` is still wrong today)
- `domain/phasing.ts` ↔ `calculateDistribution()` in `ProgressTracking.tsx` (two engines,
  already diverged: Bell vs S-Curve are distinct in one, identical in the other)
- CLAUDE.md's stated rules ↔ what is mechanically enforced
- Investigator's belief ↔ reality (F6)

**The structural reason divergence goes undetected:**

> **The ports-and-adapters seam — the codebase's greatest strength — is also what blinds the
> test suite.** All enforced testing runs against the memory fake. The memory fake has no
> schema, no constraints, no RLS, no migrations. The entire class of defects that hurt this
> month is, by construction, invisible to CI.

This was predicted. The July audit's root cause #3 was "tooling does not enforce the
conventions the codebase claims." Wave 1 fixed the **code** half (ESLint + the debt ratchet).
The **data/schema** half was never closed — and that is precisely where every failure came from.

## 4. Remediation

| # | Action | Status |
|---|--------|--------|
| 1 | **Vocabulary contract test** — parse CHECK sets from migrations, assert code-vocabulary ⊆ db-vocabulary. No database required, runs in CI. | ✅ done — `tests/unit/vocabulary-contract.test.ts`. Immediately found F5. |
| 2 | **Legible e2e failures** — fail fast on page errors and print console output, instead of 30 silent timeouts. | ✅ done |
| 3 | **Boot-matrix test** — assert the app boots under each `VITE_ADAPTER` with only that adapter's env. Prevents F1's class. | ✅ done |
| 4 | **Migration drift check** — `npm run db:drift` diffs repo migrations against the live ledger. | ✅ done (local; needs credentials, so not a CI gate) |
| 5 | **Fix `changes.status`** (F5) | migration `0047` written + verified by test; **awaiting `db push`** |
| 6 | **#26 dev/prod split** | open — the structural enabler behind F2, F3, F5 |
| 7 | **`enforce_admins` decision** | open — a gate that can be bypassed decays into decoration |

### The principle worth keeping

Three of the six failures were wrong *diagnoses*, not wrong code — including the apostrophe
theory, "the orphan ledger entries are harmless", and "`changes.status` is a safe superset"
(which was F5 hiding in plain sight, missed by reading three lines of a dropdown instead of
all four). Every time the live system was actually probed, it contradicted a plausible theory.

> **Cheap reconciliation beats confident inference.** The probe costs seconds; the theory costs
> days. Build the reconciliation into the pipeline so it does not depend on anyone remembering.
